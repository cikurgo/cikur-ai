CIKUR GO — BCGO CLEAN + AGENT PRESENCE AUDIT v6

BASELINE
- Derived from cgo-unified-22-bcgo-clean-v5.
- The old Medicine/Executor surface remains removed from BCGO UI and BCGO engine.

BCGO CLEAN CHECK
- ORGAN_REGISTRY remains the 12-file BCGO monitor registry.
- No Medicine/Executor/Captain/Workbench/Approval/Patch/Rollback diagnostic UI or bridge was reintroduced.
- BCGO remains a realtime monitor/state producer.

AGENT CGO LIVE PRESENCE
- agentcgo.html now publishes live Agent presence while the Agent is operationally ONLINE.
- Location is obtained only from browser geolocation permission.
- Presence is written to mitra_applications/{uid}_agent under presence.*.
- Presence contains active/available, live coordinates, accuracy, 0.05-degree cell, server timestamp, and source marker.
- Position updates are throttled to 15 seconds unless the Agent moves at least 25 metres.
- Offline/stop/pagehide paths attempt to mark presence inactive; freshness also prevents stale presence from being treated as live.

BCGO REALTIME SENSOR
- bcgo.js now listens to approved Agent CGO presence in Firestore in realtime.
- BCGO_STATE exposes agentPresence for the future radar surface.
- Only active, approved, fresh, usable-location Agents enter the live presence set.
- Accuracy worse than 1000m is not treated as usable live presence.

CUSTOMER GEO-SCOPED PATH
- cikur-config.js provides findNearbyAgentPresence().
- Customer queries only the nearby 0.05-degree cells (maximum 25 cells), then applies exact Haversine distance and freshness checks.
- Query result is capped at 20 Customer-facing Agents.
- Customer-facing records contain no Agent coordinates.
- cgo-customer.js automatically wires this resolver into the internal Brain when available.
- No global Agent scan is performed by Customer discovery.

ARCHITECTURE NOTE
- Firestore remains infrastructure/realtime data transport only.
- No external AI/API or Firebase Functions-like runtime was introduced.
- The visual radar is intentionally not added yet; this milestone establishes its live data contract first.
