CIKUR GO — LIVE AGENT CGO RADAR DESIGN NOTE

1. RADAR CORE
- BCGO_STATE.agentPresence is the authoritative internal live feed for the admin radar.
- Radar should render only fresh presence records.
- Each Agent marker should carry state: READY / BUSY / STALE.

2. GEO BEHAVIOR
- Customer center is not exposed to other Customers or Agents through the radar feed.
- Admin radar may visualize operational Agent coordinates because it is an internal monitoring surface.
- Customer discovery receives distance/availability, never Agent coordinates.

3. LIVE ANIMATION
- New Agent: soft pulse-in.
- Moving Agent: interpolate marker position instead of jumping.
- Lost heartbeat: fade toward STALE, then remove after freshness expiry.
- Cell transition: marker continues smoothly while the data query scope changes behind the scenes.

4. RADAR LAYERS
- Center: CIKUR GO / selected operational area.
- Ring 1: 1 km.
- Ring 2: 3 km.
- Ring 3: 5 km.
- Optional extended ring: 10 km.
- Counter: Fresh Agent, Ready, Busy, Stale.
- Filter: Agent type, READY/BUSY, radius.

5. SCALE
- Do not redraw the entire DOM for every Firestore snapshot.
- Maintain a keyed marker store by Agent ID.
- Apply only added/changed/removed records.
- Keep the radar view separate from the raw BCGO telemetry list.
- For large populations, the admin radar should eventually consume a server-side/Firestore geo-partition contract rather than a single unbounded collection snapshot.

6. CUSTOMER DISCOVERY
- The Customer view should say “Agent CGO aktif di sekitar kamu” and return nearest verified results.
- It must never expose another Agent's exact coordinate.
- Location permission remains explicit and current.

7. NEXT IMPLEMENTATION
- Build radar UI only after this presence contract is verified against the real Firebase project and Firestore Rules.
- Then add incremental marker diffing, heartbeat age display, radius controls, and live connection indicators.
